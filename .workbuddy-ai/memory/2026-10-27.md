## 项目通读（初次上手）

- 业务：Etsy 店铺 KushtarGifts 的宠物纪念/定制产品，需按客户提供的宠物名批量制作**名字印章（STL）**，用于在黏土/饰品上压印名字；STL 再导入 Bambu Studio 排盘打印（1211.3mf 为打印工程，单盘 62 个模型，extruder 4）。
- 技术链路：`names/namesMMDD.txt`（每行一个名字）→ Python 调 OpenSCAD（`-D name=... -D base_len=... -D letter_spacing=...`）→ `stamp_template.scad` 生成 → `output_stl/output_stlMMDD/<NAME>.stl`。
- 关键脚本：
  - `program/batch_3Dnames.py`：**当前主力**（Tkinter GUI + 拖拽 + 配置持久化 `all_in_one_config.json` + 线程执行 + 日志队列），PyInstaller 打包为 `program/dist/PJ1Program.exe`。
  - `program/all_in_one.py`：早期 CLI 版（check / batch / font 子命令），无 GUI。
  - `main.py` / `beifen1.py`：最早期版本，路径与 names 文件硬编码。
  - `font.py` + `program/提取字体.py`：fontTools 改字体（hmtx 统一 advanceWidth=1300、A-Z 上移 200、改 name 表、声明等宽），产出 `Special_Elite/Daziji_V1..V5.ttf`。
- 参数：底座 6mm 宽 × 10mm 高，字高 6mm、挤出 6mm，整体 mirror([1,0,0]) 使压印后文字正读；底座长度按字符数映射 2→18mm … 13→65mm；letter_spacing 默认 1.2。
- 数据现状：`names/` 168 个 txt、共 1288 条名字；`output_stl/` 148 个批次目录；长度分布集中在 4–6 字符。
- 已知风险点：
  1. 映射表只到 13 字符，`SGT. SPRINKLES`(14)、`AUDREY  HEPBURN`(15) 会被跳过（静默 `[跳过]`）。
  2. `len(name)` 把空格也算字符（如 `MOO DENG`=8），多词名字底座偏长、字距偏空。
  3. 名字含 `& . -` 与纯数字（2015/2026）——`&` 在 OpenSCAD text() 中可能渲染异常，需实测。
  4. 系统未安装 Daziji/Special Elite 字体（C:\Windows\Fonts 无匹配），模板仍用 `font_name="Arial"`，与做好的等宽字体未打通。
  5. 模板缺少 `letter_spacing` 参数声明，`-D letter_spacing=` 实际不生效（变量未在 scad 中使用）——待确认。
  6. 各批次 names 存在重复名字（同一文件内重复），会重复生成/覆盖同名 STL。

## 工程化重构 + 打包交付（stampgen 2.0.0）

把原来的批处理脚本重写为 `src/stampgen/` 包（config / paths / fonts / metrics / template / openscad / validate / batch / cli / gui），旧脚本移入 `legacy/`（program/ 的 venv、dist 未动，旧 exe 仍可运行）。

**三条核心诉求的落地方式**
1. 换字体：字体放 `fonts/`，运行时生成 fontconfig 配置经 `FONTCONFIG_FILE` 注入 OpenSCAD 子进程，免安装。
2. 调粗细：字重（字体族+style 下拉）+ `offset(delta)` 几何加粗 0~0.25mm（`weight_offset_mm`）。
3. 定宽自适应：固定目标宽度，反解字号与间距。短名字顶到字号上限后放大间距，仍不够则 `underfill` 并给出建议宽度；长名字判 `too_long` 并算出建议底座宽度。

**关键技术结论（OpenSCAD 2021.01 实测）**
- `size` 非毫米：advance 与墨迹的放大比例不同 → `ADVANCE_SCALE=4/3×1.01725`、`INK_SCALE=4/3×1.04159`。
- 宽度与字号严格成正比 → 单次廉价探针（0.2mm 挤出）即可反解精确字号，并顺带吸收 GPOS 字偶距误差。
- GPOS 字偶距（如 AV/VA）随 `size × spacing` 缩放；`fit` 的纯解析预览对这类名字会偏大 ~1mm，batch 用探针标定后预测=实测。
- 曲面精度按字体轮廓节点数自适应：`$fa/$fs` 粗精度让 Daziji 从 48s 降到 7.5s。
- `valign="center"` 对整体上移过的自定义字体会偏上，改用 `baseline` + 墨迹包围盒算的偏移。
- `OS/2.sCapHeight` 不可靠（字体上移后元数据未更新），改取字形 `yMax` 中位数。

**打包（tools/build.py，PyInstaller 6.22.3）**
- 两个 onefile exe：`StampGen.exe`（windowed）、`stampgen-cli.exe`（console），各 15MB；`fonts/`、`scad/`、`assets/` 用 `--add-data` 打入。
- 打包后必踩的坑，已修：① `default_config()` 会把 `_MEIPASS` 临时路径写进配置，下次启动模板失效 → 配置留空 + `resolved_template()` 做存在性校验；② CLI 报告里的 `✓` 在 cp936 控制台抛 `UnicodeEncodeError`，整批结果打印失败 → 改 ASCII 标记 + `reconfigure(errors="replace")`；③ onefile 的窗口属于子进程，GUI 冒烟测试不能按父 PID 找窗口。
- 验证工具：`tools/verify_build.py`（跑 exe 的 fonts/fit/check/batch + 查 tkdnd 与图标）、`tools/gui_smoke.py`（启动 GUI + 窗口截图）。
- 外部字体覆盖：exe 同级放 `fonts/` 即优先于内置。
- 首次运行 fontconfig 要扫系统字体，约 60~80s（之后 3~8s/枚），GUI 日志会提示。
