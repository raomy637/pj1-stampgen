# 逐名底座宽度 + 修掉提示带的假警报

日期：2026-10-28
状态：已实现（v2.2.1）
后续：v2.2.5 又加了「字符视觉等距」（逐字定位、间隙平均分配），
会改变结果表里每个字母的落点但不改变总宽。最新状态见 [CHANGELOG](../../CHANGELOG.md)。
前置：v2.2.0（单模式限宽）已完成

## 一、一个必须先修的 bug

用户截图里的提示带：

> ! 清单里「方法喱」的墨迹高 6.85mm，含加粗 0.36mm 共 7.21mm，
> 超过底座宽度 6.6mm，会被压到 5.46mm。建议底座宽度 ≥ 7.3mm　[采用]

但结果表里 8 个名字，前 7 个全是「正常 6.00mm」，第 8 个「方法喱」是「跳过」。

### 6.85mm 是假数据

「方法喱」三个汉字在这个字体里**一个字形都没有**（`v_bboxes` 命中 0）。
`ink_ratio()` 拿不到包围盒时会退回「26 个大写字母的并集」当替身，
于是算出 0.8223 em → 6.85mm。这个数是替身的，不是「方法喱」的。

而它本来就会被 `validate_batch` 判为 `non_ascii` 跳过，**根本不参与生成**。

### 用户看到的现象

| 步骤 | 实际发生 | 用户感知 |
|---|---|---|
| 看到提示带 | 说有个名字要 7.3mm | 「哦，底座不够」 |
| 点「采用」 | 底座 6.6 → 7.3，真的改了 | 参数区那个框悄悄变了 |
| 看结果表 | 7 个名字本来就正常，方法喱照样跳过，**一行都没变** | 「我点了，什么都没发生」 |
| 0.25 秒后 | 提示带消失（因为 7.21 ≤ 7.3+0.3） | 「提示没了，但到底改了什么？」 |

根因不是按钮，是**提示带用了一个不会生成的名字**。

### 修法

1. `check_spec()` 只用「真会生成」的名字算字高：
   非空、长度 ≤ `max_chars`、全 ASCII 无控制字符、字体有全部字形。
2. `ink_ratio()` 拿不到包围盒时**不再回退到大写字母样本**（那是虚高），
   改为返回 `cap_ratio()`；调用方（`fit`）本来就会先做 `missing_chars` 检查。
3. 提示文案带上「当前值」和「差多少」，不再只说「建议 ≥ X」。

修完之后这个例子里**根本不该出现提示**（7 个正常名字最大 6.59 ≤ 6.6+0.3）。

## 二、需求：逐名底座宽度

### 用户原话

> 很多名字里如果是只有一两个底座宽度需要变化，我觉得应该在结果预览里增加 1 列，
> 单独列出，其他符合要求的可以用默认的宽度参数

即：底座宽度（Y 向截面）从**全局值**变成**逐名值**。

```
底座宽 6.6mm（默认）
  TESS    6.6   ← 用默认
  LEELA   6.6   ← 用默认
  DAISY   6.6   ← 用默认
  Daisy   7.2   ← 小写 y 下沉，单独加宽，字号仍 6.00
  WALKER  6.6   ← 用默认
```

技术上本来就支持：模板是 `cube([base_len, base_width, base_height])`，
`base_width` 逐名传即可。字母在 Y 向按墨迹居中，加宽底座不会让字偏移。

### 为什么优先加宽而不是缩字

字号是视觉主体。一套印章**字一样大**比**截面一样宽**重要得多。
加宽底座只是让某个印章胖一点，缩字号会让它看起来像次品。

用户已确认：截面不一致可以接受，但预览里必须体现出来。

### 算法

```
ink_total = 墨迹高 + 2 × 加粗

若 ink_total ≤ 底座宽 + 0.3           → 正常，底座宽 = 全局值
若 ink_total > 底座宽 + 0.3：
    自动加宽模式（默认）
        底座宽 = 向上取整到 0.1mm(ink_total + 0.05)，字号不动 → 状态「加宽」
    缩字号模式（开关关闭）
        底座宽 = 全局值，字号压到刚好装下 → 状态「限字高」
```

`+0.05` 是留一点余量，避免墨迹正好贴边。

### 新增开关

```python
widen_base_per_name: bool = True
"""个别名字装不下时，自动加宽它的底座而不是缩字号。"""
```

界面上放在「底座宽度」旁边，勾选文案：**「个别名字装不下时加宽它的底座（不缩字）」**。

## 三、界面改动

### 1. 结果表加一列

| 序号 | 名字 | 字符 | 字号 mm | 间距 | **底座宽 mm** | 底座长 mm | 状态 |
|---|---|---|---|---|---|---|---|
| 1 | TESS | 4 | 6.00 | 1.00 | 6.60 | 25.10 | 正常 |
| 2 | DAISY | 5 | 6.00 | 1.00 | 6.60 | 30.82 | 正常 |
| 4 | Daisy | 5 | 6.00 | 1.00 | **7.20** | 23.89 | **加宽** |
| 8 | 方法喱 | 3 | — | — | — | — | 跳过 |

「底座宽」紧挨着「底座长」，两个尺寸放一起。加宽的行整行标橙色。

列宽预算：44 + 260 + 46 + 68 + 56 + **80** + 84 + 74 = 712，窗口 1136 够用。

### 2. 状态标签

| 标签 | 触发 | 颜色 |
|---|---|---|
| 正常 | 没动 | 绿 |
| 已压缩 | 只压了间距 | 橙 |
| 已缩字 | 间距到底后缩了字号 | 橙 |
| **加宽** | 底座加宽了，字号没动 | 橙 |
| 限字高 | 缩字号模式下的压字号 | 橙 |
| 超长 | 缩到下限仍超宽 | 红 |

### 3. 提示带：从「催你改」改成「已经处理好了」

这是解决「误会」的关键。现在的语气是报错，实际是已经自动处理完了。

| 场景 | 现在 | 改成 |
|---|---|---|
| 个别名字需加宽 | `! 建议底座宽度 ≥ 7.3mm [采用]` | `i 8 个名字里 1 个需要更宽的底座：Daisy → 7.2mm（其余用 6.6mm）　[统一为 7.2mm]` |
| 多数名字需加宽 | 同上 | `! 8 个名字里 6 个需要更宽的底座（最大 7.2mm），建议整体调大　[统一为 7.2mm]` |
| 留白挤满宽度 | `✕ …[采用]` | 不变（真错误，必须改） |
| 加粗过量 | `✕ …[采用]` | 不变 |
| 上限太小 | `! …[采用]` | 不变（确实是全局参数问题） |

`i` 用中性色（灰蓝），`!` 用橙色，`✕` 用红色。

### 4. 「采用」按钮的语义

按钮文字**动态化**，让用户点之前就知道它影响什么：

- 全局参数类问题（留白、加粗、上限太小、文字高度过高）→ **「采用」**
  点了就是把那个参数改成建议值，影响整批。
- 个别名字需要更宽底座 → **「统一为 7.2mm」**
  点了把全局底座宽度改成 7.2，于是**所有名字都用 7.2**（结果表 8 行的底座宽列全部变化）。

这样「点了好像没反应」不可能再发生：**底座宽这一列会把每一行的变化都显示出来**。

### 5. 点完之后的反馈

- 被改动的输入框 `focus_set()` + `selection_range(0, END)` —— 光标落在那个框、内容高亮，一眼看见
- 状态栏：`已把底座宽度统一为 7.2mm（8 个名字全部适用）`
- 提示带立即重算，条件满足就消失

不弹窗：弹窗要额外点一次「确定」，对这种"改个数字"的操作太重。

## 四、数据模型

```python
@dataclass
class StampSpec:
    ...
    base_width_mm: float = 6.0        # 语义变成「默认/最小」底座宽度
    widen_base_per_name: bool = True  # 新增

@dataclass
class FitResult:
    ...
    base_width_mm: float = 0.0        # 新增：该名字实际使用的 Y 向宽度

@dataclass
class NameResult:
    ...
    base_width: float = 0.0           # 新增：写进 manifest
```

`RenderParams.base_width` 改为取 `fit.base_width_mm`（空则回退 `spec.base_width_mm`）。

## 六、测试计划

单元层：
- 个别名字加宽：只有它变宽，其他用全局值
- 开关关闭 → 退回缩字号，状态「限字高」
- 加宽值 = `ceil((ink+2w+0.05)*10)/10`
- `check_spec` 忽略非 ASCII / 缺字 / 超长名字
- `check_spec` 在没有可生成名字时不给字高提示
- 提示文案包含当前值和差多少

端到端：
- 一批混合名字（含小写下沉），逐个 STL 的 Y 向宽度 == 该名 `base_width`
- 加宽的名字 STL 宽度确实比默认值大，字号仍 6.00

界面层：
- 截图确认「底座宽 mm」列在、加宽行是橙色
- 点「统一为 7.2mm」后，8 行底座宽全部变 7.2

## 七、风险

| 风险 | 应对 |
|---|---|
| 一批里底座宽度五花八门 | 超过半数名字需要加宽时，提示带升级为「建议整体调大」 |
| 加宽后印章明显变胖 | 底座宽列直接显示数值；加宽超过默认值 50% 时状态列额外标「加宽 +」 |
| 老用户习惯「底座统一」 | 提供开关，关掉即回到 v2.2.0 行为 |
| `ink_ratio` 改动影响已有判断 | 只在「拿不到包围盒」时行为变化，而那条路径已被 `missing_chars` 挡住 |

## 八、不做的事

- 不做「自动判断该整体加宽还是个别加宽」（让用户看列自己决定）
- 不做底座宽度的批量编辑
- 不把中文名字转成拼音（字体没有中文字形，属于另一个话题）

## 九、实现时发现的新问题

### 1. 小写 y 的轮廓自交，union 时字母会被整个丢掉

加宽逻辑做完后跑端到端，`Daisy` 渲染失败：STL 只有 684 字节、12 个三角面、
高度 10mm —— **只有底座，字母没了**。

排查过程：

| 实验 | 结果 |
|---|---|
| `text("Daisy")` 单独挤出 | 正常，1.8MB |
| 加 `translate` | 正常 |
| 加 `union` 底座 | **不闭合**，684B |
| 底座加宽到 12mm | 仍不闭合（不是贴边问题） |
| `text("TESS")` + union | 正常 |
| `offset(delta=0)` | 仍不闭合 |
| **`offset(r=0.001)`** | **正常，1.8MB** |

根因：这个字体（`提取字体.py` 改造过）的小写 `y` 轮廓有重复点或自交。
单独挤出时 OpenSCAD 走普通渲染，看不出问题；一旦和底座做 union 就要过 CGAL，
CGAL 报 `ERROR: The given mesh is not closed!` 然后**只导出底座、退出码仍然是 0**。

这是最危险的一类 bug：**静默产出没有字的印章**，打印出来才发现是白板。

修法两层：

1. `export_stl()` 检查 OpenSCAD 输出里的 `not closed` / `Unable to convert to
   CGAL_Nef_Polyhedron`，命中就抛 `OpenSCADError`（不再静默）
2. `batch` 捕获后自动用 `outline_fix=0.001` 重渲染一次 —— 模板里
   `offset(r=outline_fix)` 会重建多边形，0.001mm 的外扩可忽略

`offset(delta=)` 用的是斜接方式，不能修复自交；只有 `offset(r=)` 的圆角方式
会重新三角化，实测能修复。

### 2. 其余与方案的偏差

| 项 | 方案 | 实现 | 原因 |
|---|---|---|---|
| 提示级别 | 只有红/橙 | 新增蓝色 `INFO` | 「已经自动处理好了」不该用橙色（橙=还需要你注意） |
| 「多数名字需加宽」 | 未定义阈值 | 至少 2 个且过半 | 1 个名字特殊不代表「全局值设小了」，1/1 也报会显得啰嗦 |
| 状态栏 | 只报底座长范围 | 底座宽不一致时补报宽度范围 | 否则用户不知道这批有胖有瘦 |
| 窗口尺寸 | 1160×880 | 1160×920，日志区 3 行 | 几何区多了一行勾选框，结果表被挤到只剩 7 行 |
